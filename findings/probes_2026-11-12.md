# Supplemental probes (2026-11-12): printer, 20-dim scaling, config parsers

After codex review 4, three cheap probes targeted the highest-expected remaining
yield: printer round-trip over all valid constructs, a wider scaling sweep, and
mutations of the config/document parsers.  All three are bounded negative
results; no new defect was found.  This is recorded so the campaigns are not
repeated.

Raw data: `out/fmt_probe/` + `out/fmt_probe.jsonl`, `out/scale_probe.json`,
`out/cfg_cases.jsonl` + `out/cfg_results.jsonl` + `out/cfg_pkg_results.jsonl`.
Harnesses: `harness/fmt_probe.py`, `harness/scale_probe.py`,
`harness/config_fuzz.py`.

## 1. Printer round-trip over 43 constructs — 0 failures

One minimal program per language construct, each verified with
`moonc syncheck`, then `moonfmt` → re-parse → re-format:

Covered: async fn/await, try/catch, raise, suberror, `is` patterns, guard,
defer, attrs, extern, impl blocks (`impl S with m`), trait impl (`impl T for S
with m`), trait declarations, derive, type aliases (`type` / `pub type`), tuple
structs, labelled/optional args, generics, or-patterns, range patterns, array
patterns, nested tuple/match/if, string/char escapes incl. `\u{...}`, hex/bin/
octal/underscore literals, map/array literals, destructuring, `for (k,v) in`,
pipe, `S::method`, `mut` fields, `pub`/`priv`, test/bench blocks.

| check | result |
|---|---|
| files | 43 |
| fmt exit 0 | **43/43** |
| formatted output re-parses | **43/43** |
| idempotent | 43/43 |
| internal `~+`/`~-` leak | **0** |
| keyword loss | **0** |
| `()`/`[]` removed | **0** |

Observed normalizations (all re-parse and were spot-checked for behaviour):

* `defer { e }` → `defer e`
* `try { e } catch { ... }` → `e catch { ... }` (postfix catch)
* `y? : Int = 1` → `y~ : Int = 1` (optional marker rewritten; `f(x=1)` still
  prints the same result before/after, verified with `moon run`)

An earlier flag on trait-impl was a local test-fixture error (invalid source
without `with`); after correcting the fixture it disappears.  No printer defect
in this population.

## 2. 20-dimension scaling — only the known interpolation anomaly

19 dimensions × k ∈ {4…512}, plus the interpolation control; `moonc syncheck`
and `moonfmt` measured with per-child `wait4`:

Dimensions: generic type-parameter count, labelled-argument count, or-pattern
length, nested `Array[...]` depth, nested tuple-type depth, nested `match`
depth, nested `try/catch` depth, async-fn count, array-pattern length, trait
method count, impl method count, doc-comment count, enum constructor count,
struct field count, semicolon/let chain, extern count, match-arm count, nested
`if` depth, string-interpolation segments.

| metric | range |
|---|---|
| syncheck doubling ratio | 1.2–1.8× (no super-linear growth) |
| moonfmt doubling ratio | 1.3–2.1×, except interpolation **10.5×** |
| failures / timeouts | 0 |
| flagged | only `interp` (reconfirms P1) |

`nested_match` / `nested_try` formatted output grows ~4.5× / 4.2× per doubling
(indentation), and their fmt time follows output size — output-driven, not an
algorithmic anomaly.  The P1 reproduction on the interpolation control still
shows the ~10× per-doubling curve.

## 3. Config/document parser mutations — 14,000 cases, 0 anomalies

Stages (all read by moonc):

* `moon.pkg`: `moonc syncheck moon.pkg` (the config parser itself);
* `doc.mbt.md`: `moonc syncheck doc.mbt.md`;
* `x.mbti`: `moonc build-interface -pkg x/y -i prelude -o x.mi x.mbti`.

Seeds are *valid* minimal files; mutations are byte flip/insert/delete/replace,
truncation, duplication and token insertion from a config alphabet.

| run | cases | ICE/crash/timeout/silent |
|---|---:|---:|
| mixed stages (`cfg_results.jsonl`) | 10,000 | **0** |
| moon.pkg-only rerun (`cfg_pkg_results.jsonl`) | 4,000 | **0** |

Diagnostics stay in the ordinary error classes: `E4192` invalid `moon.pkg`
construct, `E3002` parse error, `E3001` lexer error, `E3100` invalid mbti.
No silent failures and no resource anomaly (each case ≤5 s, 4 GiB cap).

Caveat: the seeds are valid-config mutations, so the *specific* F1 crash shape
(`s(1,1,...` truncated, 101 B) and F4's invalid-UTF-8 byte are not in this
mutation family; this campaign does not claim F1/F4 rediscovery.  A directed
F1 seed exists in `poc/f1_moon_pkg_segv`.

## Conclusion

This round's expected new-defect yield (1–2 tooling/resource families) did not
materialize in these three probes.  The remaining probability mass is in the
actions codex ranked above coverage work: controlled baseline comparison,
third-party mooncakes packages (external validity / miscompile), and the
defect/oracle validation pass.  Printer, 20-dim scaling and config mutation are
now closed as bounded negatives and should not be repeated without a new
hypothesis.
