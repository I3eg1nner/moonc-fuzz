# 类型导向生成（codex 第 9 轮排第一）：首个矩阵与裁决

日期 2026-11-12。依据：codex 看过 `moonbit-compiler` 老源码后的排序——
**① 类型导向生成 → ② 语法边界重建 → ③ 老编译器做差分 oracle（限 4h）**。

它同时纠正了两点：

* 老仓库的 parser 是**代码式**的（没有明显的 action/goto 表），
* 二进制里 379 个 `menhir_goto_*` **不是 379 个不同产生式**。

## 1. 实现的矩阵（`harness/typegen.py`）

六个形状，4 个应通过、2 个应报错：

| 形状 | 内容 | 应通过 |
|---|---|---|
| generic_trait | 泛型 + trait 约束 + 多 impl | ✓ |
| enum_match | 枚举（元组变体）+ 穷尽 match | ✓ |
| nested_generic | `Array[Option[Int]]` + 闭包 | ✓ |
| visibility | priv 类型 + 内部访问器 + pub 入口 | ✓ |
| no_impl | 调用泛型但缺 impl | ✗（E4018） |
| bad_visibility | 跨包构造私有类型 | ✗（E4033 等） |

## 2. 结果（240 个程序）

| 指标 | 值 |
|---|---:|
| 应通过 × 接受率 | 160/160 = **100%** |
| 应报错 × 拒绝率 | 80/80 = **100%** |
| 诊断码分布 | 4018 / 4024 / 4033 / 0002 / 0003 / 0029（各 40） |
| 覆盖（40 个样本，重放 moon 命令） | union **1,771** `Moonc.*`，均值 1,227/项目 |
| **对既有 7,916 并集的新增** | **0** |

## 3. 裁决：按 codex 自己的放弃线，这个矩阵到头了

codex 给的放弃条件：*"accepted cases add fewer than 50 `Moonc.*` functions and no
new type-related diagnostic classes against an equal-budget baseline"*。

* 新函数 **0 < 50**；
* 新诊断类：只有 `E4033`（跨包私有构造）可能算新，其余 4018/4024 在既有语料里都有。

⇒ **不再扩展这个矩阵**。它留下了两样东西：六个可复用的形状模板、以及一条负结果
（"类型正确的程序"并不自动带来新覆盖，瓶颈仍是**类型组合的多样性**，与 21.5% 那轮的结论一致）。

## 4. 顺带修的工程坑

`moon check --dry-run -v` 输出里的 `-i '$MOON_HOME/lib/core/...'` 是**带引号的 shell 变量**，
直接 `split()` 会把 `$MOON_HOME` 当字面量 → 每条命令早退（只命中 ~296 个函数）。
替换引号并展开 `$MOON_HOME` 后才是正常的 ~1,227 函数/项目。`harness/typegen_cov.py` 已处理。
